Scope

Two limits, both of which make these numbers a lower bound. First, a crawler only sees nodes that accept incoming connections — anything behind NAT that never listens is invisible to it. Second, “rated good” is the seeder’s own quality gate (port, services, protocol version, reported height and sustained uptime), not a live reachability test: a spot check found most nodes it rates as not-good still accept connections. Treat the good count as “confidently serveable”, not as “how many nodes are up”.

Are nodes agreeing on the chain?

Each node reports its block height during the handshake. A cluster stuck well behind the rest is the first visible sign of a chain split — so the fork nodes are split here into those on an enforcing release and those not, to show whether the two groups are drifting apart.

Stable nodes list, for fixed-seed runners

If you run a curated, fixed-list seed rather than a crawler, the hard part is knowing which nodes are actually reliable. This is that evidence: fork nodes this crawler has found consistently reachable, with the figures behind the claim.

Read first

This is evidence to curate from, not a list to serve unexamined. A curated seed is resistant to Sybil attacks precisely because a human chooses it — an attacker cannot get in by running nodes. Serving this list verbatim would hand that property away, because anything that keeps its uptime high ends up here automatically. Use it to inform your judgement, not to replace it.

How this is measured
  • A crawler connects to each node on port 8333 and completes a Bitcoin handshake, recording the services, block height and software it reports. Nothing here is second-hand.
  • Fork nodes are identified by service bit 28 (0x10000000, NODE_BLAKE2B).
  • A node reporting the fork bit while running software with no BLAKE2b support is still counted, but flagged, since it is either misconfigured or misreporting.
  • “Rated good” is not a liveness check. It is the seeder’s internal gate, combining correct port, advertised services, protocol version, reported block height and sustained uptime history. A node can be perfectly reachable and still not clear it — sampling 15 nodes rated not-good, 12 accepted connections. The count is deliberately conservative, and the honest reading is “at least this many”.
